# FJCAI 2027 — PCRR

Executable P1–P5 experiments for **Perturbation-Consistency Risk Ranking for Reliable Tabular Classification Under Feature Corruption**. CPCR is a candidate method; no superiority or novelty is assumed.

The existing project is `G:\My Drive\FJCAI2027_PCRR` on this computer and `/content/drive/MyDrive/FJCAI2027_PCRR` on Colab. Original data and `00_DOWNLOAD_UCI_DATASETS.ipynb` are preserved. No download is performed by this pipeline.

## Colab workflow

1. Wait for Drive Desktop to sync the source, configs and notebooks. Open `notebooks/01_P1_data_preprocessing.ipynb` in Colab.
2. Mount Drive, install `requirements.txt`, restart the runtime after first installation, then rerun the mount and execution cells.
3. Set `MODE='SMOKE'`, `BANK_EXTENSION=False` in each notebook. Execute P1 → P2 → P3 → P4 → P5. P5 in this mode only exports development results; Test remains unopened.
4. Inspect stage reports and `development_results.csv`. Repeat the five notebooks with `MODE='PILOT'`.
5. Set `MODE='FULL'` consistently in all five notebooks. Set `BANK_EXTENSION=True` to include Bank (450 primary cells); otherwise 300 primary cells with Bank explicitly not run. Run P1–P4, inspect the freeze, then execute P5.

All paths derive from one absolute `ROOT`. No Test-based tuning is permitted. Changing configs/source/versions creates a different experiment ID. Do not change methods after viewing Test and claim it as a fresh held-out evaluation.

## Command line

```bash
python -m pip install -r requirements.txt
python -m pytest -q
python run_all.py --mode SMOKE --stage all
python run_all.py --mode PILOT --stage all
python run_all.py --mode FULL --bank --stage P1
python run_all.py --mode FULL --bank --stage P2
python run_all.py --mode FULL --bank --stage P3
python run_all.py --mode FULL --bank --stage P4
python run_all.py --mode FULL --bank --stage P5
```

`--root` overrides the absolute project root; `PCRR_ROOT` is also supported. `--stage all` resumes completed stages. Stage-specific commands execute the requested stage with its prerequisite gate. Never run two writers against the same experiment simultaneously. MLP saves epoch/optimizer/best-checkpoint state. P5 resumes verified condition caches; an interrupted statistics step can be rerun using existing predictions.

Pinned primary dependency versions are in `requirements.txt`; actual versions, source hashes and raw manifest hashes enter the experiment signature. Training automatically uses CUDA if available for MLP; persisted models and benchmark inference use CPU consistently. Deterministic algorithms are requested, but cross-platform bitwise equivalence is not claimed.

## Results and acceptance

Canonical artifacts live in `results/<experiment-id>`, `checkpoints/<experiment-id>`, `data/processed/<experiment-id>`, `data/splits/<experiment-id>` and `reports/<experiment-id>`. Root-level result tables and stage reports are convenience copies of the latest applicable run; always cite experiment IDs. SMOKE never stands in for FULL acceptance.

P4 creates `results/<experiment-id>/frozen_protocol.json` with a separate checksum, and FULL publishes `results/frozen_protocol.json`. P5 verifies every recorded artifact, library/config/source signature and raw dataset checksum. Root-level `frozen_protocol.json` remains NOT_RUN until a real FULL freeze exists.

`summary.csv`, `per_seed_results.csv`, `metrics_by_corruption.csv`, `ablation_results.csv`, `statistical_summary.csv`, figures and `scientific_report.md` are generated by FULL P5. Prior to that, root tables have headers only. No artificial experiment results are supplied.

Read `reports/METHODOLOGY.md` for duplicate handling, temporal splitting, metrics, tie policies and statistical limitations. Read `reports/IMPLEMENTATION.md` and `reports/FINAL_ACCEPTANCE.md` for what was actually tested locally.

## Dataset failure

P1 verifies **all three datasets**, even when a run excludes Bank. Missing files, wrong labels/shapes or checksum mismatch raise `DATASET_NOT_READY` and stop. Inspect the original download notebook and UCI archive before any repair; never overwrite raw data or silently refresh a manifest to accept a changed file.
